# Настройка: публикация ICP в группу через GitHub Actions

Бесплатно, без сервера и без Railway. Шесть шагов, все делаются один раз.

## 1. Отдельный бот

Напишите @BotFather → `/newbot` → получите токен.

**Заведите именно нового бота, не переиспользуйте токен от другого своего
бота.** Две причины. Если тот бот где-то запущен и держит `getUpdates`, попытка
прочитать обновления тем же токеном вызовет конфликт поллинга. И утечка одного
токена не должна задевать сразу два проекта.

## 2. Группа

Создайте группу, добавьте туда нового бота и дайте ему право отправлять
сообщения. Если группа приватная — этого достаточно.

## 3. Узнать chat_id группы

Отправьте в группу любое сообщение, затем откройте в браузере:

```
https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates
```

Найдите `"chat":{"id":-100…}` — это и есть `TELEGRAM_CHAT_ID`. Число
отрицательное, минус — часть значения.

Токен никуда мне не присылайте: он нужен только вам, чтобы положить его в
секреты GitHub на шаге 5.

## 4. Репозиторий

Создайте репозиторий на GitHub и запушьте туда эту папку:

```bash
cd /c/icp-watcher
git remote add origin https://github.com/<вы>/<репозиторий>.git
git push -u origin master
```

**Публичный или приватный — это про деньги, а не про безопасность.** Секретов в
коде нет, они лежат в GitHub Secrets в обоих случаях. Разница в квоте Actions:

- **публичный** — минуты не тарифицируются вообще, можно проверять хоть каждые
  5 минут;
- **приватный** — 2000 бесплатных минут в месяц, и Actions округляет каждый
  запуск вверх до минуты. Текущие полчаса дают ~1470 минут в месяц и в лимит
  укладываются. Если захотите чаще — либо публичный репозиторий, либо следите
  за расходом в Settings → Billing.

## 5. Секреты

Settings → Secrets and variables → Actions → New repository secret:

| Имя | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен из шага 1 |
| `TELEGRAM_CHAT_ID` | `-100…` из шага 3 |

## 6. Проверка

Actions → **ICP watch** → Run workflow → mode `digest` → Run.

Через несколько секунд в группе появится сводка. Если нет — откройте лог
запуска: скрипт печатает цену и то, что решил сделать, а текст ошибки Telegram
выводится без токена.

## Что дальше происходит само

- **Каждые 30 минут** — проверка. Если ICP вырос на 10% и более за 24 часа,
  в группу уходит уведомление.
- **Раз в сутки в 09:00 по Ташкенту** — полная сводка: цена, оборот,
  соотношение покупок и продаж.

Повторно то же уведомление не придёт: после срабатывания бот «разряжается» и
взводится обратно, только когда рост опустится ниже 8%. Состояние хранится в
`state.json`, который workflow коммитит обратно в репозиторий — у cron-задачи
нет другой памяти между запусками. Коммиты помечены `[skip ci]`, чтобы не
запускать workflow сами на себя.

## Поменять пороги

В `.github/workflows/icp.yml`, блок `env`:

```python
# alert_levels.py — уровень: значение, ниже которого он снова взводится
LEVELS = {5.0: 4.0, 10.0: 8.0}
```

Зазор между уровнем и точкой перевзвода обязателен, иначе цена, колеблющаяся у
самого порога, будет присылать уведомление каждые полчаса.
